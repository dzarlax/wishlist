Gift Modal Action Zone

Repository: D:\Projects\Code\Personal\wishlist. Branch: codex/gift-modal-polish. Created: 2026-06-14.

Task Summary

Redesign the gift details modal so it helps the guest decide and act: understand the gift, open the external page, and reserve it. At the same time, fix role-specific behavior so owners do not see guest-only reservation CTAs.

Current Behavior

  • ViewGiftModal.svelte uses a heavy header with Просмотр подарка, then image, title, badges, sections, metadata, and a bottom CTA.
  • The CTA is visually separated from price and external link.
  • Labels are uppercase and feel more administrative than consumer-facing.
  • Owner view currently still shows the guest action Забронировать for available gifts.
  • The modal can show creation/reservation metadata that is not useful for guests.

Desired Behavior

  • Use a lighter modal header: close button plus useful status, not a generic Просмотр подарка title.
  • Limit image height to keep title, price, and actions in view.
  • Use natural section labels: Описание, Цена, Ссылка without uppercase styling.
  • Add a sticky bottom action zone with price on the left and primary/secondary actions on the right.
  • Guest available: price + external link + Забронировать.
  • Guest reserved: show status and allow secret-code actions where appropriate.
  • Owner: show owner-safe details and external link, but do not show Забронировать.
  • Hide creation date from guest view; keep it only for owner if we still need it.

Wording Decision

The review suggested Открыть товар, but Wishlist links can point to a course, experience, donation page, or product. I recommend Открыть страницу or Перейти к подарку. My preference is Перейти к подарку: it says what the user is trying to do, without reducing everything to a shop item.

Likely File Changes

  • frontend/src/lib/ViewGiftModal.svelte: main modal layout, sticky action footer, role-specific actions, image sizing, softer labels.
  • frontend/src/lib/locales/{ru,en,sr}.json: modal status/action copy.
  • Possibly frontend/src/App.svelte only if event wiring needs adjustment.

Test Plan

  • cd frontend && npx eslint src/lib/ViewGiftModal.svelte src/App.svelte.
  • cd frontend && npm test if snapshots/assertions are affected.
  • cd frontend && npm run build.
  • Browser QA in dev compose: owner available gift, guest available gift, reserved gift, mobile-width modal.

Risks And Rollback

  • Sticky footer can overlap content on mobile; add bottom padding to modal body and verify small viewport.
  • Role-specific CTA logic can hide a useful action accidentally; verify owner and guest separately.
  • Rollback is local to ViewGiftModal.svelte and locale copy.
